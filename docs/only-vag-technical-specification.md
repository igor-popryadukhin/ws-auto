# Техническое задание на разработку сайта автосервиса Only‑Vag

## 1. Общее описание

Only‑Vag — сеть сертифицированных автосервисов, специализирующихся на обслуживании автомобилей концерна VAG (Volkswagen, Audi, Škoda, Seat, Porsche, Bentley и др.). На текущем сайте [only-vag.ru](https://only-vag.ru) представлены основные разделы: информация о сервисе, специальный калькулятор стоимости, страницы конкретных марок авто, акции, прайс-лист, отзывы, контакты, гарантии, форма претензий, вакансии и блог с полезными статьями. Новый сайт должен сохранить структуру и функциональность, но быть реализован на современном стеке (Nuxt 4 с Composition API, Node LTS, Tailwind CSS и TypeScript), обеспечивать SSR и высокую производительность, а в будущем предоставлять API для получения контента.

**Цель:** создать интуитивно-понятный, быстрый и адаптивный сайт автосервиса, который увеличит конверсию клиентов и позволит легко расширять функционал.

## 2. Технологический стек

- **Frontend:** Nuxt 4 на основе Composition API (Vue 3) с TypeScript. Использовать сервер-сайд рендеринг (SSR) и статическую генерацию (SSG) для скорости и SEO. Подключить модуль `@nuxtjs/tailwindcss`.
- **Backend:** Node.js LTS.
  - использовать Nuxt как fullstack-фреймворк (Nitro) с серверными API для обработки форм, или
  - вынести backend отдельно (например, на Express) с REST/GraphQL API.
- **База данных / CMS:** предусмотреть headless-CMS (Strapi, Directus) либо собственную БД (PostgreSQL). Все сущности (акции, цены, статьи, вакансии, отзывы, заявки) должны храниться в БД и выводиться через API.
- **Стилизация:** Tailwind CSS для компонентов, настройка `tailwind.config.js` с корпоративными цветами (черный, белый, оттенки серого, красный для акцента). Пользовательские utility-классы для переходов и анимаций.
- **Типизация:** компоненты и серверный код на TypeScript с явными интерфейсами для данных.

## 3. Структура сайта и функциональные требования

### 3.1 Общие компоненты

- **Шапка (Header):** лого, контактные телефоны, часы работы, ссылка на главную, выпадающее меню «Марки авто», ссылки на «Акции», «Прайс-лист», «Контакты», верхнее меню с гарантией, отзывами, страницей претензий, вакансий, полезных статей, а также поисковая строка и иконки соцсетей (VK, Telegram). В адаптивной версии бургер-меню.
- **Подвал (Footer):** информация о юридическом лице, список услуг по категориям (ремонт, обслуживание и полезная информация), ссылки на страницы, контактные телефоны и социальные сети, ссылка на политику конфиденциальности.
- **Навигация по маркам:** карточки брендов (Volkswagen, Porsche, Audi, Škoda, Seat, Bentley, Jetta и др.) с изображениями автомобилей. При клике открывается страница бренда.
- **Форма расчёта стоимости работ:** многошаговый опросник (7 шагов) с прогресс-баром и полями для описания работ, выбора марки/модели, состояния автомобиля, желаемого филиала, контактных данных. Доступна на главной, страницах марок, акций и прайс-листа. Данные отправляются на сервер; предусмотреть валидацию (обязательные поля, формат телефона и email), защиту от спама (reCAPTCHA), сообщение об успешной отправке.
- **Карта и контакты:** блок с перечнем сервисов (адрес, телефон, кнопка «Маршрут Яндекс Навигатор») и встроенная интерактивная карта Яндекс с несколькими метками. Для интернациональной версии предусмотреть Google Maps.
- **FAQ:** секция «Вопросы и ответы» с аккордеоном. Данные хранятся в БД и выводятся через компонент.

### 3.3 Функциональность форм

- Клиентская и серверная валидация, маска телефона `+7 (XXX) XXX-XX-XX`.
- Понятные сообщения об ошибках.
- Модульный подход: базовый компонент `<BaseForm>` с возможностью переиспользования полей и отправки на различные эндпоинты.
- Данные форм сохраняются в БД и отправляются на email менеджерам. Антиспам: CAPTCHA, throttling.
- После отправки показывать окно «Спасибо» и ссылку на WhatsApp/Telegram.

### 3.4 Дополнительные модули

- **Поиск по сайту:** полнотекстовый поиск по статьям, прайсу и страницам (Algolia или встроенный поиск в БД).
- **Панель администратора:** headless CMS (например, Strapi) для управления контентом: прайс, акции, статьи, вакансии, FAQ.
- **Отзывы:** интеграция с внешними сервисами (Яндекс.Карты); возможность добавить собственные отзывы.
- **Мультиязычность:** подготовить структуру для дополнительных языков (Nuxt i18n). По умолчанию русский.

## 4. Дизайн и UX

- **Цветовая палитра:** тёмный фон (#111–#1a1a1a), контрастные белые/серые области, яркий красный для кнопок и акцентов.
- **Шрифты:** современный без засечек (Montserrat или Inter) с поддержкой кириллицы; крупные заголовки и комфортный интерлиньяж.
- **Верстка:** адаптивная, на мобильных одна колонка, бургер-меню, форма расчёта во всю ширину.
- **Изображения:** оптимизированные (WebP/AVIF), lazy-loading, обязательные `alt`-теги. В фотогалерее — адаптивная сетка, возможность зума.
- **Иконки:** SVG (Heroicons) и изображения автомобилей.
- **Анимации:** минимальные, плавные, без влияния на производительность.
- **Доступность:** корректные `aria`-атрибуты, контрастность, навигация клавиатурой.

## 5. Нефункциональные требования

- **Производительность:** оптимизация под Core Web Vitals, SSR, кэширование (ISR), оптимизация изображений и шрифтов, исключение лишних зависимостей.
- **SEO:** динамические мета-теги (title, description, keywords, Open Graph, Twitter Card), микроразметка Schema.org (Organization, Service, Article), карта сайта и `robots.txt`, ЧПУ-адреса (например, `/poleznye-stati/dq200-dsg-problemy`).
- **Безопасность:** защита от XSS/CSRF, HTTPS, безопасные заголовки, защита форм.
- **Бэкапы и логирование:** журналы обращений и ошибок, регулярные резервные копии БД.
- **Интеграция аналитики:** подключение Google Analytics/Яндекс.Метрика, отслеживание событий (отправка форм, клики, скролл до конца страницы).

## 6. План расширения и API

- Подготовить систему к получению контента из внешнего API: страницы загружают данные через асинхронные запросы (например, `useFetch` в Nuxt).
- Разработать интерфейсы TypeScript для сущностей: `Brand`, `Service`, `PriceItem`, `Promotion`, `Article`, `Review`, `Vacancy`, `Complaint`, `Application` и др.
- Предусмотреть слой репозиториев (composables) для работы с API. При отсутствии API — мок-данные или статические JSON.
- Формы отправляют данные на серверные функции (endpoints) и в будущем могут интегрироваться с CRM (Bitrix24, AmoCRM).

## 7. Тестирование и приёмка

- **Тестирование:** модульные и e2e-тесты (Jest, Cypress) для проверки отображения страниц, работы форм, мобильной адаптивности, SEO-мета-тегов.
- **Производительность:** аудит Lighthouse с устранением проблем, влияющих на LCP, FID, CLS.
- **Юридические согласования:** политика конфиденциальности, обработка персональных данных перед запуском.
